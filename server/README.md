# Голосовая практика ТОПА · пробный запуск

Готовый код для схемы: **запись на татарском → Gladia → подтверждение расшифровки → Qwen через Яндекс AI Studio → ответ текстом**. Печатать реплику и устанавливать модель на сервер не требуется. Озвучивания ответов нет.

## Что уже реализовано и что ещё не подключено

- Кнопка «Практика с Топой» под названием модуля, только для татарского. Открытие после вводного урока проверяется в интерфейсе.
- Материал только первого урока: 7 основных слов, союз «һәм», два примера, цели и правила наставника в `curriculum.json`. Название первого урока — «Знакомство», фактическая ситуация — магазин и пальто, а не представление по имени.
- Запись микрофона, остановка, автоматический предел длительности, расшифровка, подтверждение или перезапись, чат и счётчик. Микрофон отключается при остановке, закрытии и сворачивании страницы.
- API-сервер, проверка кода команды, отдельные разговоры, постоянные лимиты в SQLite, защита от дублирующих платных запросов, обработка таймаутов.
- Ключи не передаются браузеру и модели. История беседы формируется сервером, произвольные инструкции/model/tools из браузера не принимаются. Ответы отображаются через `textContent`.
- **Платные API не проверены реальными ключами**: проверены код, контракт запросов, обработка аудио и сценарии на имитациях. На опубликованной странице сервер пока не подключён, и интерфейс сообщает об этом. Демонстрационных ответов в рабочей версии нет.

Это закрытый пилот для команды, не публичная система аккаунтов. Код команды даёт доступ к общему лимиту пилота. Ограничение по прохождению урока пока является интерфейсным: прогресс ТОПА остаётся в localStorage. Сервер всегда разрешает только учебный набор `tt-intro-v1`, но не подтверждает личное прохождение урока. Перед массовым запуском нужны настоящая авторизация, подтверждённый сервером прогресс и индивидуальные квоты.

## Что подготовить

1. Небольшой Linux-хост с Docker и постоянным диском. GPU не нужен. Для данного пилота задан предел контейнера 512 МБ и 1 CPU; это ограничение ресурсов, а не гарантия пропускной способности. Нужны доступ к интернету и HTTPS-домен для API.
2. Аккаунт Gladia, API-ключ и доступ к `/v2/upload` и асинхронному распознаванию **Solaria-1**, язык `tt`. Не выбирать Solaria-3: для этого подключения требуется модель с татарским. До пополнения убедитесь, что сервис принимает ваш аккаунт и способ оплаты; доступность из РФ этим кодом не подтверждена.
3. Проект Яндекс AI Studio, каталог, API-ключ с правами генерации текста и точный URI доступной модели Qwen из текущего каталога. Модель должна поддерживать Chat Completions, `reasoning_effort: none` и JSON-ответ. Если выбранная модель эти параметры не поддерживает, адаптер нужно согласовать с её документацией; автоматического дорогостоящего переключения модели нет.
4. Случайный длинный код для доступа команды. Это не API-ключ провайдера.

Платежи: хост + распознавание + генерация текста. Распознавание и наставник оплачиваются отдельно. SQLite работает на диске того же хоста. Код не обещает бесплатный тариф и не создаёт аккаунты/оплату автоматически.

## Настройка

Работайте с полной папкой проекта. Не загружайте секреты в GitHub или чат.

1. Скопируйте `server/.env.example` в `server/.env` на компьютере или хосте.
2. Заполните:

   - `GLADIA_API_KEY` — секрет Gladia;
   - `YANDEX_API_KEY` — секрет Яндекса;
   - `YANDEX_FOLDER_ID` — идентификатор каталога;
   - `YANDEX_MODEL_URI` — полный URI выбранной модели, например `gpt://идентификатор-каталога/идентификатор-модели`; значение нужно скопировать из своего каталога;
   - `PILOT_ACCESS_CODE` — случайный код не короче 20 символов, рекомендуются 32 случайных байта;
   - `ALLOWED_ORIGINS` — точные адреса разрешённых сайтов через запятую, без пути и завершающего слеша. Для действующего сайта: `https://andezitus.github.io`. Локальные адреса добавляйте отдельно при необходимости;
   - `PRACTICE_ENABLED=true` — включение только после настройки предыдущих полей.

3. Сгенерировать код можно локально командой Node.js (результат сохраните в своём менеджере паролей и `.env`, не в файлах сайта):

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

4. Из корня проекта запустите:

```sh
docker compose -f server/compose.yaml up --build -d
```

Контейнер слушает только `127.0.0.1:8080` на хосте. Настройте в панели хостинга HTTPS reverse proxy на этот адрес. Разрешите POST-тела до 2 МБ и время ожидания ответа не менее 90 секунд. Сохраняйте том `practice-data` при обновлениях. Внешний порт 8080 открывать не требуется.

5. В **публичном** `practice-config.js` укажите только адрес API:

```js
window.TOPA_PRACTICE = Object.freeze({ apiBase: 'https://ВАШ-ДОМЕН-API' });
```

Здесь не должно быть секретов или кода команды. Загрузите обновлённые клиентские файлы на GitHub Pages. Серверные файлы выполняются на хосте; GitHub Pages их выполнять не умеет.

6. В ТОПА выберите татарский, пройдите первый урок и откройте «Практику с Топой». Введите код команды, ознакомьтесь с отправкой данных, запишите короткую фразу, проверьте расшифровку и нажмите «Отправить Топе».

Самостоятельный локальный запуск без Docker: установите Node.js **24+** и FFmpeg из официальных источников; проверьте `node --version` и `ffmpeg -version`. Из корня:

```sh
node --env-file=server/.env server/practice-server.mjs
```

Откройте `http://localhost:8080`, включив этот origin в `.env`. На localhost сайт автоматически использует API по тому же адресу. Через `file://` запись и API не проверяйте. Для удалённого браузера нужен HTTPS.

## Ограничения расходов

По умолчанию: до 15 секунд на запись, 8 ответов наставника на разговор, не более 12 записей с учётом перезаписей, до 3 разговоров на один вход. Для всего пилота — **100 заданий распознавания и 100 вызовов наставника за всё время существования базы**, а не на каждый день/браузер. Ответ ограничен 320 выходными токенами; вся история ограничена размером урока и числом реплик.

Лимиты резервируются в транзакции до платных запросов и не сбрасываются после рестарта или перезагрузки страницы. Неопределённый результат обращения не приводит к автоматической повторной платной отправке. При ошибке сохраняется использованная попытка. Перезапись — отдельная попытка. Опрос существующего задания не создаёт новое задание. При сбое сети кнопка проверки отправки повторяет тот же idempotency key.

100 записей по 15 секунд — до 25 минут переданного аудио; провайдер может применять собственное округление или минимальную тарифицируемую длительность. Для генерации учитываются и входные токены. Эти пределы ограничивают объём, **не являются денежным лимитом в рублях**. До запуска сверяйте тарифы в кабинетах; включите доступные ограничения провайдеров. Для немедленной остановки установите `PRACTICE_ENABLED=false` и перезапустите контейнер. Не удаляйте базу для обновления кода: это сбросит счётчики.

## Данные и безопасность

- Исходное аудио обрабатывается в памяти, нормализуется FFmpeg в WAV 16 kHz mono, не сохраняется локально и передаётся Gladia. Сервер проверяет фактическую декодированную длительность; передавать внешние аудио-URL клиенту не разрешено.
- На сервере остаются расшифровки и ответы в SQLite до 24 часов (можно сократить `RETENTION_HOURS` до 1–24). Очистка раз в минуту при работающем сервере и при запуске. При явном завершении беседы её тексты удаляются из активных таблиц сразу. Это логическое удаление; SQLite WAL, резервные копии и снимки диска могут иметь отдельный срок хранения. Не включайте несогласованные резервные копии с учебными разговорами.
- Истёкшая сессия недоступна через API. Токены хранятся хешами на сервере, в браузере — только в памяти. Ввод кода не сохраняется в localStorage.
- Данные также обрабатывают два провайдера. Удаление на нашем хосте не означает удаления у них. До реальной записи проверьте их актуальные сроки хранения, настройку использования данных и доступные способы удаления. Gladia Free по опубликованным условиям может хранить запись и расшифровку до года; у платных планов сроки другие. Этот адаптер с загрузкой и опросом не совместим с Enterprise Zero Data Retention, где нужны callback и внешний аудио-URL.
- Настройте минимально необходимые права ключей и отключите ненужное логирование у провайдеров. В прикладные журналы не пишутся реплики, заголовки или тела ошибок API. `.env`, база и временные данные исключены из Git и Docker-образа. HTTP-сервер отдаёт только публичные файлы, не `server/`.
- У наставника нет tools, выполнения кода, произвольного доступа к базе/файлам или другим разговорам. Пользовательская расшифровка передаётся только как сообщение `user`. Права и квоты исполняются кодом.
- Промпт и проверка JSON не гарантируют, что модель никогда не уйдёт от темы или не ошибётся по-татарски. Проверка формата не является полноценной проверкой смысла/безопасности ответа. Для пилота доступ ограничен командой; до публичного запуска нужны языковая проверка и отдельные проверки содержания.
- Фонетика автоматически не оценивается: модель видит только расшифровку. Ошибку распознавателя нельзя считать доказательством ошибки ученика.
- Запускайте один экземпляр Node-сервера на одной SQLite-базе. Не масштабируйте контейнер в несколько реплик без переработки координации; отдельная база пока не требуется. Это небольшой пилот, не инфраструктура на 50 параллельных пользователей.

## Проверки

```sh
node --test tests/practice.test.mjs
node tests/assets.test.cjs
node tests/intro-lesson.test.cjs
node tests/flashcards.test.cjs
node tests/streak.test.cjs
node tests/mobile-viewport.test.cjs
```

Новые тесты используют имитации API, не расходуют баланс и проверяют цепочку, доступ, изоляцию сессий, лимиты, параллельные запросы, повторные отправки, формат ответа, секреты в ошибках и реальное ограничение аудио через FFmpeg. Для живой проверки после настройки: «Исәнмесез», «Җылы пальто», «Матур һәм җылы пальто», «Рәхмәт»; перезапись ошибочной расшифровки; закрытие при записи; достижение лимита. Проверить формулировки с носителем татарского.
